# v2.5.438 — Chrome 快取自動更新

## 背景
手機 Chrome 清除「快取圖片和檔案」後，組隊問題恢復正常，顯示舊版前端程式快取是重要原因之一。本版加入快取更新機制，避免瀏覽器長期沿用舊版 HTML、JavaScript 或 CSS。

## 本版內容
- 新增根目錄 `sw.js` Service Worker。
- 導航頁面、同源 JavaScript 與 CSS 使用 network-first：先向伺服器取得最新版本，成功後更新執行快取。
- 網路中斷時才使用先前快取的相同 URL 作為離線備援。
- Service Worker 註冊使用 `updateViaCache: 'none'`，並在遊戲啟動時呼叫 `registration.update()` 檢查更新。
- 所有 HTML 中帶版本查詢參數的 JS/CSS URL 從 `2.5.437` 更新為 `2.5.438`（57 處）。
- 偵測到既有控制器切換時，只顯示安全更新提示，不自動重整；玩家可先手動儲存，再自行重新整理。

## 存檔安全
- 不清除 LocalStorage。
- 不讀取或改寫角色、背包、倉庫、隊伍資料。
- 不清除瀏覽器網站資料或 Cookie。
- 不在戰鬥或掛機中強制重新載入頁面。
- Service Worker 只處理同源 GET 導航、`.js`、`.css`；圖片、音訊及外部資源仍由瀏覽器原本機制處理。
- 網路失敗時使用同 URL 的快取版本，不將網路錯誤寫成空白遊戲資料。

## 使用條件與限制
- Service Worker 需要 HTTPS 或 localhost；GitHub Pages 的 HTTPS 網站符合條件。
- 首次註冊後，瀏覽器需至少完成一次後續頁面載入，該頁才會由 Service Worker 控制。
- 更新不會在遊戲中途自動重整；若提示更新，先手動儲存，再重新整理套用。
- 此機制不會跨手機與電腦同步玩家存檔。

## 測試
- 新增 `tools/v2_5_438_cache_update_regression.js`，檢查版本號、57 個版本化 JS/CSS 資源參照、Service Worker 註冊、更新檢查、network-first、離線備援及不清除玩家資料；靜態與模擬執行測試共 8/8 通過。
- 發佈前需在 GitHub Pages HTTPS 網站實際測試首次註冊、後續更新、Chrome 重新整理及離線備援；本地 Node 測試不等同真實手機瀏覽器驗收。
