# v2.5.465 寵物個體指定恢復

## 本版修正
- v2.5.464 已以 `petUid` 保存同種類寵物的獨立培養紀錄，但圖鑑僅能按陣列順序恢復。
- 新增 `hatchPetByUid(eggId, petUid)`，先驗證寵物蛋種類、個體 UID、孵蛋器與寵物蛋數量，再移除指定紀錄並恢復該個體。
- 圖鑑逐筆顯示保存個體名稱、親密度及飢餓度；只有在沒有出戰寵物、且有孵蛋器及寵物蛋時才能恢復。
- 已保存個體對應的蛋視為保留數量；只有 `持有蛋數 > 可恢復個體數` 時才開放孵化新個體，避免新孵化消耗舊個體的恢復蛋。
- 原本 `hatchPet(eggId, restoreSaved)` 保留，確保舊 UI／其他呼叫端相容。

## 尚未開放
- 野外捕捉仍未接入。專案現有道具資料有馴服道具名稱，但尚未建立完整的「目標怪物—捕捉道具—台灣伺服器捕捉率—成功後寵物蛋」映射；不可用其他伺服器的機率代替台灣 RO。
- 進化仍未接入。未完成全部材料、個體條件及結果道具的台灣伺服器核對前，不開放消耗材料操作。

## 驗證
- `tests/test_pet465_instance_selection.js`：指定個體恢復、其他個體資料不變、無效 UID 不消耗道具、道具不足不恢復、圖鑑逐筆顯示及新孵化保留數量。
- 既有寵物回歸測試全部保留；HTML 資源引用無遺漏，查詢版本、`VERSION.txt`、Service Worker runtime cache 統一為 2.5.465。
- 不清除 LocalStorage、不重置玩家存檔。
