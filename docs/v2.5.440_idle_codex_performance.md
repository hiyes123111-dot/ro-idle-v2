# v2.5.440 — 長時間掛機與圖鑑效能優化

## 本版範圍
依使用者指定，先處理原優化清單第 4、5 項：
4. 長時間掛機的記憶體使用量
5. 圖鑑搜尋與卡片／怪物資料切換速度

## 長時間記憶體
- 圖鑑搜尋索引由無上限物件快取改為 4,096 筆 LRU Map。
- 快取只存小型搜尋字串，不保存 DOM 節點或遊戲狀態物件；最近使用項目優先保留。
- 既有傷害飄字上限 48、暴擊特效上限 18、戰鬥紀錄依角色與分類保存上限 1,000 筆的機制保留。
- 既有動畫計時器仍在動畫結束／停止時清除；主戰鬥循環仍在停止時 clearInterval。
- 本版沒有清除玩家存檔、戰鬥紀錄或瀏覽器資料。

## 圖鑑效能
- 搜尋、收藏狀態及職業限制先對 ID 陣列過濾，再建立顯示 row；避免每次輸入搜尋字都先為整份圖鑑建立數千個暫存物件。
- 圖鑑池完整簽章（涵蓋大型 ITEMS、CARDS、MONSTERS 與地圖資料）改為最多每 10 秒重新驗證一次，避免每次鍵入搜尋字都掃描整份資料庫並組合巨大字串。
- 新增 `invalidateCodexPoolCache()`；若遊戲運行中有資料載入器追加或替換圖鑑資料，可呼叫此函式立即重建。未主動失效時，動態資料最遲於下一次完整簽章檢查被發現。
- 原有搜尋欄位、繁中名稱、別名、怪物種族／屬性、分類、收藏狀態、近期卡片、職業限制及分頁行為保留。

## 不在本版修改
- 傷害公式、技能倍率、卡片效果、掉落機率、怪物 AI。
- 角色、隊伍、背包、倉庫、離線掛機結算及存檔格式。

## 測試
- `tools/v2_5_440_codex_memory_performance_regression.js`：5/5 通過，包含 20,000 個不同搜尋 ID 後快取仍限制在 4,096 筆、ID 優先過濾、圖鑑池簽章節流與既有長時間上限檢查。
- `tools/v2_5_440_cache_update_regression.js` 驗證新版 Service Worker 快取更新；`tools/v2_5_440_long_session_ui_caps_regression.js` 驗證長時間 UI 特效上限。另執行既有圖鑑搜尋／圖片、圖鑑池、戰鬥紀錄保存及相關回歸測試。
- 本地測試不等同 Android Chrome 實機長時間記憶體測量；需用大量道具角色連續掛機數小時驗收。
