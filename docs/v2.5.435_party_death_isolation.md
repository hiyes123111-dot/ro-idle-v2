# v2.5.435 組隊倒地與玩家安全區傳送隔離

## 檢查結論
- 專案共有 61 個職業定義；`onPlayerDown()` 與地圖切換函式沒有依職業 ID 分流或指定特定職業傳送安全區。
- `state.mapId` 的一般切換由 `changeMap()` 處理；死亡返回安全區由 `onPlayerDown()` 處理。
- 組隊採傭兵快照及 `withAlly()` 暫時切換 `state` 的架構，故死亡處理必須識別目前操作者，不能把隊友狀態當成玩家狀態。
- `monsterAttackAlly()` 本身使用 `allyTakeDamage()`，會將隊友標記倒地，不會呼叫玩家死亡傳送流程。
- 靜態追蹤未找到任何職業專屬的 `changeMap()`／安全區傳送呼叫。因此尚不能只憑原始碼斷定使用者遇到的特定職業是哪一個直接觸發者。

## 本版防護
`onPlayerDown()` 新增 `_allyActing` 隔離：
- 若目前在 `withAlly()` 隊友換身期間呼叫，僅將該隊友標記為倒地並設定復活等待時間。
- 不增加玩家死亡次數。
- 不修改玩家地圖、怪物清單或玩家 HP/SP。
- 不執行玩家的安全區 UI、音樂及地圖重繪流程。
- 玩家本人死亡時，原本返回安全區、全隊復活、恢復 HP/SP 的流程保持不變。

## 注意
此版先修正可明確隔離的隊友／玩家死亡處理風險；由於現行怪物攻擊隊友走 `allyTakeDamage()`，而玩家死亡回城走 `onPlayerDown()`，仍需使用者重現時提供觸發職業與戰鬥紀錄，才能確認原始症狀是否另有職業技能或玩家自身死亡因素。
