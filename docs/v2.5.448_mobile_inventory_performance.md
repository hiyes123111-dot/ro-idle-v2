# v2.5.448 — 大背包／自動販賣／卡冊與紫箱效能優化

## 修正範圍
- 自動販賣視窗左右欄改為每欄先顯示 100 筆，提供「載入更多」；不再一次建立整份大量道具 DOM。
- 自動販賣視窗建立背包數量 Map，避免右欄每一種道具都重新掃描背包。
- 自動販賣清單依背包陣列建立有生命週期的排序快取；背包變更時與背包索引一起失效。
- 執行自動販賣改為 Set + 單次背包掃描，最後一次替換背包及失效快取；保留鎖定道具、個體裝備、遺物與原售價規則。
- 修正大量開箱的批次參數未真正傳入同步開箱函式的問題。原先非同步包裝雖宣稱分批，但實際一次可能開到 999 個；現在每批 25 個、間隔 50ms。
- 紫箱／卡冊批次開啟時先彙總背包新增數量，批次結束才失效背包快取及重畫獲得通知。
- 卡冊限定卡池每輪分批開啟只掃描一次，整輪共用 Set；不延遲圖鑑資料更新。
- 保留每次獨立抽選、原抽取權重、卡冊／箱子圖鑑紀錄、稀有獎勵提示及每批存檔。

## 資料安全
- 不變更玩家存檔格式、道具數量語意、卡片資料、裝備、戰鬥公式或抽獎機率。
- 背包快取僅在執行階段存在，不寫入存檔。

- 全部 JS 語法檢查與既有背包／卡冊／快取回歸測試於打包前執行。
