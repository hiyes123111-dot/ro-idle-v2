# v2.5.441 存檔效能與安全優化

## 本版修改
- `saveGameThrottled()` 改為排程式合併：同一個 5 秒窗口內多次戰鬥／統計更新共用一次寫入，計時器不會因為頻繁呼叫而反覆重設。
- 新增 `flushPendingSave()`，頁面觸發 `pagehide` 時提交最後一批排程存檔。
- 直接呼叫 `saveGame()` 的重要操作仍同步寫入；並取消已排程的重複寫入。
- 讀回存檔仍逐字比對完整 JSON，維持資料完整性；由於寫入前已解析及驗證 payload，讀回完全一致後不再重複 `JSON.parse` 一次。
- 寫入失敗時節流計時也會更新，避免高頻統計在儲存空間不足時每秒重試；重要操作仍可直接重試。
- 手動存檔只有在 `saveGame()` 回傳成功時才顯示成功訊息，避免儲存失敗卻顯示已儲存。
- 切換存檔格、匯入及刪除前先處理舊角色的待存檔，避免延遲回呼寫錯欄位或刪除後又被待存檔復活。
- 保留原有存檔格式、角色識別驗證、寫入後讀回驗證、配額錯誤提示、隊友快照隔離及舊存檔相容遷移。

## 安全界線
- 不改用非同步 IndexedDB、不拆分存檔 key、不壓縮或重寫玩家資料格式。
- 不清除玩家存檔、不自動覆蓋其他存檔欄位。
- `saveGame()` 仍是同步寫入；重要裝備／角色／隊伍操作不延遲。只有原本使用 `saveGameThrottled()` 的高頻戰鬥統計更新採合併排程。
