# v2.5.437 新角色存檔驗證與防止角色消失

## 問題與原因
`createCharacter()` 原本會呼叫 `saveGame()`，但 `saveGame()` 遇到 LocalStorage 寫入失敗時只顯示提示（舊版甚至曾靜默略過），而 `confirmCreate()` 無論首次存檔是否成功都直接 `enterGame()`。因此角色可能只存在記憶體，玩家遊玩一段時間後重新整理，讀取不到新角色。

這是程式碼可直接確認的缺陷；是否每次都由手機儲存空間額度觸發，仍須依實際瀏覽器錯誤訊息確認。

## 本版修正
- `saveGame()` 改為回傳成功／失敗布林值。
- 寫入前驗證存檔 JSON 必要欄位，寫入後立即讀回並比對完整字串及角色身分（名稱、職業、建立時間、地圖）。
- LocalStorage 寫入失敗、讀回不一致或存檔欄位錯誤時，回傳失敗並顯示明確提示；容量不足會給出專用提示。
- 不再為了序列化而直接改寫 `state.allies` 中的即時隊友物件；只在序列化副本中排除隊友重複怪物資料。
- `createCharacter()` 回傳首次存檔結果。
- `confirmCreate()` 只有在首次存檔驗證成功後才進入遊戲；失敗時留在建立畫面，避免讓玩家誤以為新角色已安全保存。
- 舊存檔缺少 `createdAt`／`lastActiveAt` 時，讀取時補上相容欄位。
- `_allyActing` 期間仍維持原本不將隊友快照寫入玩家欄位的保護。
